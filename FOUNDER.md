# FOUNDER BUILD RULES

These rules represent approved cross-project development behavior.

Do not add new permanent rules automatically.
New rules must be proposed for founder approval.

## RULE-001 — Test Before Scaling Changes

For bulk or potentially destructive operations:

1. Test a small sample.
2. Inspect the result.
3. Dry run where possible.
4. Request approval when risk requires it.
5. Apply the full operation.
6. Verify the final result.

Status: ACTIVE

---

## RULE-002 — Implementation Is Not Deployment

Code existing locally does not prove production state.

Production claims must be verified against the real production system.

Status: ACTIVE

---

## RULE-003 — Preserve Approved Decisions

Do not unnecessarily replace previously approved product or design decisions while working on unrelated tasks.

Status: ACTIVE

---

## RULE-004 — Claims Are Not Evidence

Agent statements are not sufficient proof of completion.

Prefer observable external signals.

Status: ACTIVE

---

## RULE-005 — Protect Production

Potentially destructive production actions must not execute silently.

High-risk operations will eventually require explicit founder approval.

Status: ACTIVE
